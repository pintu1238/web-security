# Backend implementation requirements

Work only in `Backend/` except you may append ignore rules to `.gitignore`. Do not modify frontend, README, or config.py (has user edits). No commits. Do not spawn subagents. Implement with Python stdlib, existing Flask, requests, PyMuPDF. Existing `.venv/Scripts/python.exe` has packages. Read current files before modifying. Build factory `create_app(test_config=None)` and keep global `app`; serve `frontend/web/index.html` on `/`, static assets from `/assets/`. Use `NITISHIELD_DB` or app config `WORKSPACE_DB` for a separate SQLite workspace database default `Backend/data/workspace.db`. No model import at app startup. Existing `/api/search` must continue JSON question/results contract but use fast real local-PDF keyword excerpt retrieval by default; leave legacy search_engine.py untouched. Tests must exercise real SQLite/PDF behavior and malformed requests. Write tests first, run failing, then implement and run passing.

JSON API exact frontend contracts:

- `GET /api/health` => `{status:'ok'}`.
- `GET /api/dashboard` => `{profile, tasks, scans, documents, activity, stats:{compliance_completed,compliance_total,security_score,open_findings,documents_count}}`. security_score null until scan, scans newest first with full findings. activity is `{id,title,detail,created_at,type}[]`, derived from actual actions. Any missing optional data can be empty.
- `GET /api/settings`, `PUT /api/settings` => profile object `{business_name,owner,email,website,business_type,address,notifications}`. Default business_name 'My business', owner '', website '', business_type 'IT / Software', notifications true. Validate values/types/length/email and http(s) website, only supported keys.
- `GET /api/tasks` => array `{id,title,description,category,priority,status,due_date}`; seed six starter recommendations (privacy notice, access control, backups, employment records, business registration records, incident response plan), status pending, categories Legal/Security/Operations, priorities high/medium/low; no invented legal deadlines, due_date nullable. `POST /api/tasks` body title,category,priority,due_date => created object, 201. `PATCH /api/tasks/<id>` body status (`pending`/`completed`) => object. `DELETE /api/tasks/<id>` => `{ok:true}`. Validate ids, enums and lengths.
- `GET /api/scans` => array full scan records. `POST /api/scans` body `{url,authorized:true}` => persisted scan `{id,url,score,created_at,findings:[{id,title,severity,status,description,recommendation}],checks_passed,checks_total}`. Passive HTTP response/header checks only (HTTPS, CSP, HSTS, X-Content-Type-Options, frame protection, Referrer-Policy). Do not claim active vulnerability scan. SSRF defense: reject credentials, private/reserved/loopback/linklocal addresses IPv4/6 and internal-only domains; validate and pin resolved public addresses for actual request or equivalent robust no-rebinding solution; validate each redirect, bounded redirects/timeouts and response size; TLS verification required. Failure returns meaningful JSON 400/422/502, never fake results. Consent required. Tests mock network only, validate private destinations, redirect safeguards, missing consent and header classification.
- `GET /api/scans/<id>/report` => downloadable text report.
- `POST /api/search` body `{question}` => `{question,answer,source:'local_documents',results:[{chunk_id,text,metadata:{law_name,page_number,file_name,url},retrieval_method:'keyword'}]}`. Extract from actual local PDFs, rank matching meaningful keywords. Return no-results clearly, no fabricated answer. Handle greeting. No external service required. Keep `GET /api/conversations` => array `{id,question,answer,results,created_at}` and `DELETE /api/conversations` => `{ok:true}`. Save real successful question/answer exchanges. Bound question length.
- `GET /api/knowledge` => array `{id,title,file_name,pages,size,url}` of actual local PDF docs. `POST /api/knowledge` multipart field `file` accepts parseable PDFs <=10 MB, reject empty/image-only PDFs clearly, safe generated basename, returns doc 201, reject duplicates by content if practical. `GET /api/knowledge/<id>/download` securely serves source PDF. Existing PDF included automatically. Configure test `LEGAL_DOCUMENTS_DIR` temp path; never write test data to real legal directory.
- `GET /api/documents` => array `{id,type,title,business_name,created_at}`. `POST /api/documents` body `{type,business_name,owner,address,effective_date}` where types `privacy_policy`,`employment_agreement`,`nda`,`incident_response` => created doc including `{id,title,content,...}`,201. Templates must have useful actual text and interpolated business details, clearly draft requiring review, no assertions of legal compliance. Validate required fields and ISO date. `GET /api/documents/<id>/download` => downloadable UTF-8 text.
- `GET /api/export` => JSON download containing profile,tasks,scans,documents,activity.

All API errors use `{error:'readable message'}` with appropriate 4xx/5xx. Avoid blanket swallowed errors; logger exception for unexpected server problems. Small focused modules for storage/routes/scan/knowledge/templates as needed. Local-only default startup port 5000; allow PORT env override. Include a lightweight `Backend/requirements-web.txt` if useful with Flask, PyMuPDF, requests. Runtime must work without loading sentence transformers or Chroma.

Return status and concise test result, write a report to `docs/superpowers/plans/backend-report.md` with API nuances and remaining limitations. Send main agent any contract changes promptly.
